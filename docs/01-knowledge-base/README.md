## 一线排查通用顺序（任何案例都适用）

1. **确认影响面**：全站 / 单接口 / 单可用区 / 单实例？从 SLB 错误率与 App 端错误码反推。
2. **确认时间线**：故障开始时间 ↔ 发布、变更、定时任务、容量事件。
3. **分层取证**：入口（SLB/证书）→ 主机（CPU/内存/磁盘/网络）→ 进程（线程/FD/端口）→ 依赖（DB/缓存）→ 日志。
4. **先止血后根治**：摘流、回滚、扩容、限流优先于"查清一切"。
5. **保留现场**：日志、`ps`、连接列表、堆栈/内存快照、变更记录。
6. **复盘产出**：可执行的检查项与自动化脚本，明确 owner 与触发条件。

## 使用建议

- 面试前：挑 3 个与你岗位最相关的案例，能讲清"为什么这么做"；
- 实战前：把 `automation/` 里的阈值改成你的业务口径，接入云监控事件总线；
- 排障时：先用索引表定位大类，再进对应文档看命令与判断依据。
