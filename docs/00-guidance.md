# 使用指南（Guidance）

本仓库不是"命令大全"，而是一套**可执行**的运维训练路径。请按下面顺序使用。

## 1. 角色设定

你是一名负责小红书笔记/Feed 后端的云运维工程师：

- 业务入口：App → HTTPS → SLB（7 层）→ `note-api`（多台 ECS）→ RDS MySQL / Redis / SLS
- 值班目标：**先恢复业务，再定位根因，最后沉淀自动化**
- 告警等级：P0 全站不可用 / P1 核心功能受损 / P2 局部或体验下降 / P3 观察项

## 2. 推荐学习路径

| 阶段 | 做什么 | 产出 |
|------|--------|------|
| 1. 建立地图 | 读 [知识库索引](01-knowledge-base/README.md)，理解 6 大类问题的边界 | 能在 1 分钟内说出"这类问题先看什么" |
| 2. 看懂案例 | 读 [案例手册](02-cases)，重点看"处理逻辑线"和取舍 | 能复述每个案例的止血动作与副作用 |
| 3. 动手演练 | 按编号跑 `labs/case-xx/lab.ipynb`，**先自己排查，再执行处置 Cell** | 独立完成 12 个案例 |
| 4. 固化能力 | 阅读/改造 `automation/` 脚本，接入自己的巡检 | 能解释脚本的判定条件与退出码 |
| 5. 复盘表达 | 用案例的"复盘"章节练习面试讲述（背景-动作-结果-沉淀） | 3 分钟讲清一个故障 |

## 3. Notebook 使用约定

每个 `lab.ipynb` 结构固定：

1. **场景与目标**：业务背景、告警、你要达成的结果；
2. **异常重现**：`lab.reset()` + `lab.inject_*()`，故障是真的；
3. **取证**：用命令收集证据（建议先遮住后面的解读，自己判断）；
4. **判断**：把证据收敛成结论，决定止血动作；
5. **手工处置**：执行最小必要变更，随后用 `lab.check()` 逐项验证；
6. **自动化**：重置并重新注入，运行 `automation/*.py --apply`，确认 `RESULT: REMEDIATED`；
7. **复盘**：根因、预防、生产命令对照、思考题。

执行方式：

```bash
source .venv/bin/activate
jupyter lab                     # 交互
python tools/run_all_labs.py    # 批量验证（会依次执行 12 个 Notebook）
```

> 每个 Notebook 都以 `lab.reset()` 开头，可反复执行；`lab.stop_all()` 会清理本次启动的进程。

## 4. 沙箱与生产的边界（必须理解）

- 本地故障（CPU/内存/FD/文件/证书/端口/502）是**真实复现**；
- 云侧数据（ECS/SLB/RDS/Redis/CMS/SLS）来自 `labs/common/xhs_lab.py` 的 `state.json`，返回字段对齐阿里云 OpenAPI，但**不会真的调用云 API**；
- `lab.sh()` 是一个"路由式 Shell"：`df/du/systemctl/journalctl/ss/lsof/find/mysql/redis-cli` 等按语义渲染，
  其余命令（`curl/openssl/lsof -p` 等）真实执行；
- 所有写入都在 `labs/.runtime/<case>/`，不会修改宿主机系统文件。

因此：**流程、判断、命令、字段是生产级的；资源和账单是模拟的。** 面试时请如实说明。

## 5. 每个案例的自检清单

完成一个案例后，确认自己能回答：

- [ ] 告警对应的指标是什么？阈值合理吗？
- [ ] 我先做了什么止血动作？为什么不是另一个？
- [ ] 证据链是否闭环（指标 → 进程/连接 → 日志/配置 → 变更）？
- [ ] 处置动作的副作用是什么（重启丢连接、摘除降容量、清理误删风险）？
- [ ] 自动化脚本的判定条件、幂等性、失败回退是否成立？
- [ ] 如果这是 P0，我需要通知谁、多久同步一次？

## 6. 约定与风格

- 时间统一使用 `Asia/Shanghai`；
- 命令示例默认在 ECS 上以 `xhs` 用户执行，需要提权的操作会标注 `sudo`；
- 日志、实例、域名均为虚构，勿用于真实环境；
- 提交代码前请运行 `python tools/run_all_labs.py`，确保 12 个实验全部通过。

## 7. 如何写进简历（示例，不夸大）

> 独立搭建"小红书后端云运维实验室"：覆盖计算/网络/存储/数据库/可观测性 6 类 12 个高频故障，
> 为每个故障完成"告警研判 → 证据链定位 → 止血与修复 → 复盘与自动化"闭环，
> 沉淀 12 个带 dry-run/校验/退出码的自愈脚本，并用 Notebook 实现故障可复现演练（含 SLB 502、TLS 过期、RDS 1040、inode 耗尽等）。
