# 案例 04 · 安全组误删，VPC 内调用超时

> 分类：[B 网络与负载均衡](../01-knowledge-base/02-network.md) ｜ 等级：P1 ｜ 角色：一线值班

## 一、运维前

### 1.1 业务背景

`note-api` 调用内部 `feed-service`（同 VPC，`10.10.1.12:8080`）获取 Feed 聚合数据。
安全加固专项中，运维同学按"只保留 443 端口"的误操作，删除了 8080 的内网规则，
导致服务间调用全部超时。

### 1.2 触发诱因

- 安全组变更未评审、未走 IaC；
- 只删除入方向规则，未通知业务方；
- 监控只覆盖 SLB 入口，未覆盖 VPC 内部调用。

### 1.3 告警信息

| 时间 | 来源 | 内容 |
|------|------|------|
| 10:32:11 | 应用日志 | `connect timeout 10.10.1.12:8080`，错误率 41% |
| 10:33:00 | 业务监控 | Feed 聚合接口 P99 3.2s，超时率上升 |
| 10:35:20 | 用户反馈 | 首页部分内容空白 |

## 二、运维中

### 2.1 处理逻辑线

```text
区分"超时"与"拒绝"：超时多为策略丢包，拒绝多为未监听
   ↓
SSH 到调用方，telnet/nc 复测 → 超时
   ↓
tcpdump 看到 SYN 重传、无 RST → 中间设备丢弃
   ↓
对端 ss 确认 8080 在监听 → 排除应用问题
   ↓
查安全组规则与变更记录 → 缺失 8080 内网放行
   ↓
最小权限补规则 → 复测 → 观察 5 分钟
```

### 2.2 逐步拆解

**Step 1 · 复现与区分错误类型（2 分钟）**

```bash
telnet 10.10.1.12 8080
# Trying 10.10.1.12...（一直卡住）→ 超时

nc -zv -w 3 10.10.1.12 8080
# nc: connectx to 10.10.1.12 port 8080 (tcp) failed: Operation timed out
```

> 如果是 `Connection refused`，说明对端没监听，排查方向完全不同。

**Step 2 · 抓包确认（3 分钟）**

```bash
tcpdump -i eth0 host 10.10.1.12 and port 8080 -nn -c 20
# 10:36:02 IP 10.10.1.11.52134 > 10.10.1.12.8080: Flags [S] ...
# 10:36:03 IP 10.10.1.11.52134 > 10.10.1.12.8080: Flags [S] ...  （重传，无 RST）
```

**Step 3 · 对端确认（2 分钟）**

```bash
ss -lntp | grep 8080
# LISTEN 0 128 0.0.0.0:8080 ... users:(("python3",pid=3321,fd=6))
```

结论：对端监听正常 → 网络策略问题。

**Step 4 · 查规则与变更（3 分钟）**

```bash
aliyun ecs DescribeSecurityGroups --SecurityGroupId sg-bp1xhsapi
# Permissions 中只剩 443，8080 规则缺失
```

对照变更记录：10:30 安全加固操作删除了 8080。

**Step 5 · 最小权限修复**

```bash
aliyun ecs AuthorizeSecurityGroup --SecurityGroupId sg-bp1xhsapi \
  --IpProtocol tcp --PortRange 8080/8080 --SourceCidrIp 10.10.0.0/16 \
  --Description "note-api -> feed-service"
```

复测：

```bash
nc -zv -w 3 10.10.1.12 8080     # succeeded
curl -s -o /dev/null -w "%{http_code}\n" http://10.10.1.12:8080/api/v1/feed
```

### 2.3 关键取舍

| 选择 | 原因 | 副作用 |
|------|------|--------|
| 只放行 VPC 网段，不放 0.0.0.0/0 | 最小权限，避免暴露内网服务 | 跨 VPC 调用需另加规则 |
| 只放行业务端口 8080 | 降低攻击面 | 若有多端口需逐条评估 |
| 未直接回滚整个安全组 | 加固中的其他规则是有效的 | 需要逐条比对，耗时稍长 |

## 三、运维后

### 3.1 复盘

- **直接原因**：安全组 8080 入方向规则被误删；
- **根本原因**：安全组变更无评审、无 IaC、无内部调用监控；
- **做得好**：用"超时 vs 拒绝"快速缩小范围；抓包确认丢包方向。
- **待改进**：安全组未纳入基线巡检；内部调用无黑盒探测。

### 3.2 预防措施

| 措施 | 类型 | 验收标准 |
|------|------|---------|
| 安全组 IaC 管理 + 变更评审 | 流程 | 任何变更可追溯、可回滚 |
| 每日基线巡检（对比预期规则） | 自动化 | 缺失 5 分钟内告警 |
| VPC 内部关键链路黑盒探测 | 监控 | 30s 一次，超时即告警 |
| 安全组变更后自动连通性验证 | 工程 | 变更即验证 |
